# V8.1.12 — Unified Vaka panels and rules

## Principle
This release is additive. Existing Vaka functionality, legacy handlers, aliases, RP actions and the existing 18+ RP vocabulary are preserved.

## Panels
- Guest panel remains the entry point for unregistered users.
- Main participant panel is the canonical panel for registered members.
- Admin panel is restricted to the three configured administration IDs/ranks 6–8.
- RP is not a panel section: RP remains an independent chat action engine.

## Guest flows
- Registration can be started from the guest panel and continues through the existing Free Fire API registration path.
- Guild application can be completed as a questionnaire: UID, why the applicant wants to join, how they found the guild, and additional information.
- Applications are sent to the three administrators for approval/rejection.
- Legacy quick `/заявка UID` style remains supported.
- Unregistered users can propose a KV without registering first.

## Rules
- Added the supplied guild-rules image and KV-rules image to `assets/`.
- Added separate `📜 Правила гильдии` and `⚔️ Правила КВ` buttons to guest and main panels.
- Added Russian/English slash aliases and no-slash aliases for the rules commands.
- KV rules text is based on the supplied `Правила КВ.txt`.

## RP
- Existing RP dictionaries and aliases are not cleared or replaced.
- The unified RP fallback now delegates legacy/new RP actions before generic text handling can swallow them, including the existing 18+ vocabulary already present in the source.
- `!` / `.` RP aliases also consult both canonical actions and aliases.

## Storage
- `guild_applications` received additive fields for questionnaire answers and review notes.
- `kv_matches` received additive fields for future rules/proposer metadata.
- No existing rows are deleted by the migration.
